# Research

Exploratory documents for open-ended questions with no concrete design yet:
findings, options and a recommendation. Research precedes an RFC; not every
research document becomes one, and a documented "not now" is a valid outcome.

| Research                                      | Question                                                                                                                                  | Outcome                                                                                                                                                                                                                                                                    |
| --------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| [0001](0001-better-auth-oauth-provider.md)    | What does better-auth's OAuth provider do natively for core's sign-in server, and what must we build?                                     | Build on it; small defined gaps; decided and applied to the spec and epics                                                                                                                                                                                                 |
| [0002](0002-third-party-app-compatibility.md) | Which real OpenID Connect apps can sign in with core, what stops the ones that cannot, and what core should change                        |
| [0003](0003-database-connections.md)          | Can one PostgreSQL server hold core and more than ten apps safely, and should the toolkit offer limits, a pooler or both?                 | Guardrails for every instance, then an opt-in PgBouncer, both set from `sv`; for review                                                                                                                                                                                    |
| [0004](0004-a-kit-for-apps-of-their-own.md)   | What should this repository publish so apps that run on their own stop copying the same infrastructure?                                   | Publish `config` now; then notices, start-up and two stores, the apps' envelope, and a template; for review                                                                                                                                                                |
| [0005](0005-file-storage.md)                  | How should core and every app keep the files people upload, limit them, serve them and back them up?                                      | One volume, a folder per app and per person; `@sovereignfs/storage` with `fs`, then `s3`, then `git`; for review                                                                                                                                                           |
| [0006](0006-data-at-rest.md)                  | What can someone with the server's disk read, what does core's encryption protect, and what should the suite do?                          | Say it and recommend full-disk encryption; close three small gaps; secrets off the disk as an opt-in RFC; for review                                                                                                                                                       |
| [0007](0007-what-apps-share.md)               | How should the release scripts, workflows, Docker setups, agent docs and conventions every app repository carries be kept once?           | One release model first; then shared workflows, config packages and a `sync` for managed files, from the template; first slice settled                                                                                                                                     |
| [0008](0008-end-to-end-encryption.md)         | How should what apps keep for people be encrypted so the server cannot read it, for apps with core, without it, and not ours?             | One key model in `@sovereignfs/crypto` with a vault in core or in the app; signing in unlocks, the password never reaching core; built against a server that swaps keys, promised against readers; accepted, designed in [RFC 0005](../rfcs/0005-end-to-end-encryption.md) |
| [0009](0009-encrypted-files-in-core.md)       | Should core encrypt the files people keep in it, as an encrypted app does, and how?                                                       | Say what the page does now; a kit for everyone; then encrypt in the browser under the account key, as an RFC 0005 amendment; for review                                                                                                                                    |
| [0010](0010-opening-installed-apps.md)        | Can a tile in an installed core open the person's installed app instead of a browser view, on each platform?                              | A new window when installed, decided at click time; apps declare `launch_handler` and `handle_links`; desktop Chromium and Android only, iPhone and Safari cannot; spike first; for review                                                                                 |
| [0011](0011-streamlining-sign-in.md)          | Where does signing in, in core and across its apps, lose people or ask too much, and what should change first?                            | Fix three bugs and drop the invited person's second email now; then an RFC for one continuation through core's pages, and one for app sessions renewed silently against core's; for review                                                                                 |
| [0012](0012-biometric-lock.md)                | Can installed core and its apps ask for Face ID, Touch ID or a fingerprint when opened, on iPhone and Android, and what would it protect? | Only through a passkey, after a tap; a curtain protects little, so a locked session in core with keys locked behind the passkey, and apps locking through core with `max_age`; spike on devices first; for review                                                          |
