## Summary

Every Sovereign app can notify a person on a device where it is not open, with one implementation shared by all of them:

1. **`@sovereignfs/push`**, a new published package for an app's server: the app's key from its environment, encryption and signing
   on `node:crypto` (RFC 8291, RFC 8292) with no dependency, a store the app gives, an outbox that sends after the change commits, and
   the subscription route as framework-free handlers.
2. **`@sovereignfs/pwa`** gains the worker's `push` and `notificationclick` handlers, opt-in, and the browser's side of subscribing.
3. **`@sovereignfs/ui`** gains `PushControl`, "Notifications on this device", which says plainly what the device can do.
4. **The template** uses all three, so a new app has push as soon as its key exists, and a hosted app's key is generated by the
   instance. Tusk and Waymark move onto the packages; Tally, Shopper and Wallet build on them.

This milestone changes no app's behaviour that a person sees, beyond Tusk's and Waymark's control looking like every other app's, and
it changes nothing in core.

## Motivation

An installed app that cannot tell a person anything while it is closed is not what people expect of an app. Legacy did Web Push once
for its single origin (its RFC 0016). Since the split into apps of their own, Tusk and Waymark have each built it again with different
key variables, payloads, sending and storage, and Tally, Shopper and Wallet have designed three more copies (research 0013 §2). One
implementation, published, ends the drift before it triples, and gives an app made from the template push for nothing.

## Current state

- `@sovereignfs/pwa` 0.1.0 makes the worker's text and registers it; the worker keeps only what is the same for everyone and handles
  nothing else (`packages/pwa/src/worker.ts`).
- `@sovereignfs/ui` has `InstallPrompt` and `Toggle`; nothing for push.
- Tusk: `web-push` 3.6.7, `TUSK_VAPID_PUBLIC_KEY`, `_PRIVATE_KEY`, `_SUBJECT`, sealed device keys, a worker with a wake. Waymark:
  `web-push` 3.6.7, `WAYMARK_VAPID_PRIVATE_KEY`, an outbox, payloads of a kind and a path.
- The app manifest's `generate` makes a random secret of a given size once per instance (app-manifest §2.5).

## Design

### 1. `@sovereignfs/push`

Published (MPL-2.0, ESM only, no runtime dependency), for an app's server; importing it in a browser throws, as the SDK does. It needs
no core.

#### 1.1 Keys

- **`<PREFIX>_VAPID_PRIVATE_KEY`**: 32 bytes, URL-safe base64, the P-256 private key. The public key is derived from it, so there is
  one variable, not two. A hosted app lists `{ "name": "<PREFIX>_VAPID_PRIVATE_KEY", "bytes": 32 }` in its manifest's `generate`, and
  the instance makes it once; an app run another way makes one with `npx @sovereignfs/push keys`.
- **`<PREFIX>_VAPID_SUBJECT`**: the contact the push services see, a `mailto:` or an `https:` address. **Optional, and defaults to the
  app's own `<PREFIX>_URL`** when that is `https`. Apple's push service refuses a `localhost` or malformed subject, so either is
  refused at start-up when the key is set.
- `pushSettings(prefix)` reads both (and a `_FILE` form, env.md §3). It returns nothing when the key is unset: **the app has no push
  and says so**, with no default key. A key that is not a valid P-256 scalar, or a subject that is refused, throws at start-up.
- Changing the key ends every subscription made with the old one; a page finds its subscription made with another key and subscribes
  again (§2.2).

#### 1.2 A subscription

`parseSubscription(value)` accepts what `PushSubscription.toJSON()` gives and nothing more: an `https` endpoint of at most 2048
characters with no user or password in it, `p256dh` (65 bytes) and `auth` (16 bytes) in URL-safe base64, an optional
`expirationTime`. The endpoint's host must be a known push service's (Google's, Mozilla's, Apple's, Microsoft's), a list in the
package that an app can extend; nothing is sent anywhere else.

#### 1.3 What a push says

```ts
type PushMessage = {
  title: string; // 1 to 120 characters, text
  body?: string; // up to 500 characters, text
  path?: string; // where opening it goes: a path on the app's own origin, never another site
  tag?: string; // up to 100 characters; a push with the same tag replaces the last on that device
  kind?: string; // for an app's own handler in the worker (§2.1); the title is still what shows if it has none
  data?: Record<string, string | number | boolean>; // small, for that handler
};
```

It is encrypted to the device (RFC 8291 `aes128gcm`), so the push service sees only its endpoint, time and size. Serialised, it is held
under 3 KB, below the 4 KB push services accept. The icon is the app's own, from the worker (§2.1), never named by a push.

An app that keeps what it is told encrypted (RFC 0005) puts nothing of it in a push: a title such as "A card is due", or a `kind` its
worker resolves on the device, as Tusk's wake does.

#### 1.4 The store, given by the app

As the SDK's stores are (sdk §9.1), the app gives the package its store, in its own database:

```ts
interface PushStore {
  // Devices: one row per endpoint, for the account signed in when it was turned on
  saveDevice(account: string, subscription: Subscription, now: number): Promise<void>; // an endpoint another account had becomes this one's
  removeDevice(account: string, endpoint: string): Promise<void>;
  devices(account: string): Promise<Subscription[]>;
  removeAccount(account: string): Promise<void>;
  forget(endpoint: string): Promise<void>; // the push service said it is gone; its waiting pushes go too
  // The outbox
  enqueue(items: OutboxItem[]): Promise<void>;
  claim(now: number, leaseMs: number, batch: number): Promise<OutboxItem[]>;
  done(id: string): Promise<void>;
  later(id: string, at: number): Promise<void>;
  drop(id: string): Promise<void>;
}
```

- At most ten devices for an account; an eleventh replaces the one turned on longest ago.
- **The device's keys are the app's to seal.** The store keeps `p256dh` and `auth` sealed under the app's own key where it has one
  (Tusk does, with its instance key; the template does, with `lib/crypto.ts`), never as text.
- `@sovereignfs/push/testing` has an in-memory store and **a conformance suite** an app runs against its own store, so every store
  behaves the same. The package's README carries the tables for PostgreSQL and SQLite, which the template uses as they are.

#### 1.5 Sending: an outbox

- `enqueuePush(store, { account, message, now, ttlMs? })` writes one row per device of the account. **The app calls it with the
  store of the transaction that made the change**, so a change rolled back sends nothing. It never sends.
- `runPushOutbox({ store, settings, now })` claims due rows by a lease (so two processes never send one), encrypts, signs a VAPID JWT
  (ES256, `aud` the endpoint's origin, at most twelve hours), and posts with a ten-second timeout, `TTL` from the row and
  `Urgency: normal`. A `201` is done; `404` or `410` forgets the device; `429` and `5xx` try again after 1, 5 and 30 minutes; anything
  else, or a row past its `expiresAt` (four hours by default: a reminder late by more is no reminder), is dropped.
- The app runs it on a timer (the template from `instrumentation.ts`, every fifteen seconds) or from a job of its own. It returns
  counts. **Nothing logs an endpoint, a key or a message.**

#### 1.6 The route a device uses

`pushSubscriptionHandlers({ store, settings, account })` gives `GET`, `POST` and `DELETE` for the app to mount (the template at
`/api/push/subscription`). `account(request)` is the app's own: the signed-in account, or nothing (`401`).

| Method   | Body                  | Answer                                                                                      |
| -------- | --------------------- | ------------------------------------------------------------------------------------------- |
| `GET`    | —                     | `{ available: false }`, or `{ available: true, publicKey }`                                 |
| `POST`   | A subscription (§1.2) | `204`; `400` for anything else; `503` with no key                                           |
| `DELETE` | `{ endpoint }`        | `204`, removing only this device for this account; an endpoint it does not have is the same |

Each changing request is refused unless its `Origin` is the app's own; a body is read to 4 KiB at most; `cache-control: no-store`.

### 2. `@sovereignfs/pwa`

#### 2.1 The worker

`serviceWorkerSource({ …, push })` adds two handlers when `push` is given, and none otherwise:

```ts
push?: {
  name: string;   // the app's name, the title of a push that has none
  icon: string;   // a path of the app's own icon; and `badge` for the small one
  badge?: string;
  handlers?: string; // JavaScript text defining `async function onPushKind(kind, data, message)`, for an app's own kinds
};
```

- **`push`** reads the message (a push that cannot be read shows `name` and "You have a new notification"). With a `kind` and
  `handlers`, it asks `onPushKind`, which may return what to show instead; whatever happens, **it shows something**, since a browser
  stops allowing a push that shows nothing. `tag` is passed on.
- **`notificationclick`** closes the notification, resolves `path` on the worker's own origin (anything else is `/`), focuses a
  window of the app and sends it there, or opens one.
- The worker still keeps only what is the same for everyone, and **stores nothing of a push**. The rule's wording in
  `docs/architecture-rules.md` gains the two handlers.

#### 2.2 The browser's side

`@sovereignfs/pwa/client` gains:

- `pushState()`: `unsupported` (no service worker, `PushManager` or `Notification`), `insecure` (not a secure context),
  `install-first` (iPhone or iPad, not installed), `blocked` (permission denied), `off`, or `on`; it reads no browser global until
  called after mounting.
- `turnOnPush(route)`: asks for permission (it must be called from a tap), subscribes with the route's `publicKey` and `POST`s the
  subscription; if the device has a subscription made with another key, it is replaced.
- `turnOffPush(route)`: `DELETE`s, then unsubscribes. An app calls it before its sign-out form is sent.
- `usePush(route)`: a React hook with the state, `turnOn`, `turnOff`, `working` and `error`, for `PushControl`.

### 3. `@sovereignfs/ui`: `PushControl`

"Notifications on this device", for an app's settings. Framework-agnostic; state and actions come from the app (`usePush`). Its
states and words:

| State           | Shows                                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------------------- |
| `unavailable`   | Nothing (the server has no key)                                                                           |
| `unsupported`   | "This browser can't show notifications from _App_."                                                       |
| `insecure`      | "Notifications need a secure (https) connection."                                                         |
| `install-first` | "To get notifications on this iPhone, add _App_ to your Home Screen first.", with `InstallPrompt`'s steps |
| `blocked`       | "Notifications are blocked for _App_ in this browser's settings."                                         |
| `off` / `on`    | A `Toggle`, with "Get notifications from _App_ on this device, even when it isn't open."                  |
| `working`       | The toggle busy; `error` shows the reason beside it                                                       |

A story for each state and a gallery entry (design-system hygiene). The words follow `docs/design-system.md`: "app", no protocol terms.

### 4. The template

The template (`tools/create/template/app`) uses all three: `lib/push.ts` (settings and the store in SQL, sealed with `lib/crypto.ts`),
a migration with the two tables, `app/api/push/subscription/route.ts`, the worker's `push` option, `PushControl` on its settings, the
outbox from `instrumentation.ts`, `turnOffPush` before signing out, and `generate` for the key in `sovereign.manifest.json`. It sends
one push to show the path end to end: "Send me a test notification", beside the control. `docs/building-an-app.md` gains "Sending
notifications" under §10.

### 5. The apps

- **Tusk** moves to the packages: `TUSK_VAPID_PUBLIC_KEY` is read for one release (a warning if it does not match the derived key)
  and then dropped, with a note in its upgrade guide; its wake becomes `onPushKind('wake', …)`; its sealed store passes the conformance
  suite. Existing subscriptions keep working, since the key does not change.
- **Waymark** moves its outbox and sending to the package; its kinds become `onPushKind`, with words drawn in the worker as now.
- **Tally, Shopper and Wallet** name the packages in their designs and build on them in their own phases.
- Every app keeps its own decision of **what** to send and **when**; the packages decide only how.

## What this does not do

Core sending pushes, for itself or for apps; mirroring into core's bell; read and dismissed reaching the other side; messages between
servers; an unread count on the installed icon; a list of devices; hiding the words on a locked screen. Research 0013 ("Later, not
now") keeps them, and each builds on these packages.

## Alternatives considered

| Alternative                        | Why not                                                                                                                            |
| ---------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| `web-push`, as legacy and the apps | Its own HTTPS client, JWT and ASN.1 libraries in a published package, around the host list and the timeout every outbound call has |
| Tables in the package (Drizzle)    | The template has no Drizzle; the apps' schemas are their own; the SDK's store pattern already works                                |
| Sending inline                     | A rolled-back change would still notify; two processes could send twice; a slow push service would slow a request                  |
| Two key variables, both or neither | One more thing to get wrong; the public key follows from the private one, and `generate` can make a 32-byte one                    |
| A payload of kinds only (Waymark)  | Every app would write words in its worker; kept as an option through `onPushKind`                                                  |
| Each app's own control             | The same states and the same iPhone sentence, written differently each time                                                        |
| Core sends for every app now       | Out of this milestone; it needs core-app §4.1 amended and builds on these packages                                                 |

## Rollout

1. The research and this RFC, reviewed (this change).
2. `@sovereignfs/push` (19.1, 19.2), the worker and client (19.3) and `PushControl` (19.4), published.
3. The template (19.5), and the path seen on devices (19.6), before any app moves.
4. Tusk and Waymark moved, and the three designs pointed at the packages (19.7).

## Open questions

1. Should `PushControl` offer "Hide what notifications say on this device" (only the app's name), for a locked screen? Not in this
   milestone unless review asks.
2. Is a fifteen-second outbox interval right for the template, or should it run when a push is enqueued as well?
3. The list of push services' hosts: fixed in the package with a way to extend it, or only the app's?
