# Workstream 0006 — Core and every app install, and open as themselves

**Status:** 📋 Planned\

**Author:** Claude Code\

## Goal

Core installs as a complete app: it says it can be installed, announces a new version instead of swapping it silently, and offers
shortcuts. Every Sovereign app installs the same way, from one published package, and an app made from the template does so with no
extra work. In an installed core, a tile opens the person's installed app (its own window, no address bar) on the devices that allow
it, and a shortcut can open a native app. On the devices that do not allow it (iPhone, iPad, macOS Safari) the behaviour is said
plainly, and a browser tab behaves exactly as it does today.

## Definition of done

- [ ] 11.3's device rows are filled, and 11.3 is ✅
- [ ] Core's manifest has the amendment's members; the install hint and the update notice are on the Account pages and in every window
- [ ] Research 0010's device matrix is filled from observation (11.8), and RFC 0001 A5 is confirmed, narrowed or withdrawn
- [ ] `@sovereignfs/pwa` is published, and a freshly generated app installs, registers its worker and passes Chrome's install check
- [ ] The seven deployed apps declare `id`, `launch_handler` and `handle_links`, and their audit gaps are closed
- [ ] In an installed core on desktop Chrome or Edge and on Android Chrome, a tile opens the installed app; in a tab, the same tab
- [ ] A shortcut with an open-in-app address opens a native app; refused schemes are refused
- [ ] RFC 0001's status says the amendment is implemented; epic 11 is ✅

## Decisions locked

| Decision                              | Choice                                                                    | Rejected alternative and why                                                                                                  |
| ------------------------------------- | ------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| The name of core                      | Stays **core**                                                            | "Platform": already the umbrella, the root version and the `platform:*` roles; "core" is in contracts seven apps depend on    |
| How a tile reaches an installed app   | A new top-level context, chosen at click time when core runs installed    | A per-app protocol handler (desktop only, a contract change); an `intent:` address everywhere (Android only; held in reserve) |
| What core knows about an app for this | Nothing new: the launch address it has                                    | A manifest field or install detection: every platform routes by address, and detection only sees apps the site lists itself   |
| iPhone, iPad, macOS Safari            | Not possible; a browser view, said plainly                                | A workaround: none exists that a web page can use                                                                             |
| Shared PWA code                       | A new published package, `@sovereignfs/pwa`, that the template depends on | Template-only copies: the seven apps already show where copies drift (`id`, `appleWebApp`, `theme-color`)                     |
| Core and the package                  | Core keeps its own worker in this workstream                              | Moving core now: its worker has rules and tests of its own; a later task                                                      |
| Splash images                         | Still none                                                                | Since iOS 26 the manifest's colour and icon serve; dozens of images are a maintenance cost                                    |
| Shortcut deep links                   | A second, optional address, allow-listed by pattern with refused schemes  | Loosening `urlProblem`: the main address stays `https`-only, which is what a browser opens                                    |

## Leg detail

### Leg 1 — Core's fuller install

**Epic tasks:** 11.5, 11.6, 11.7

**Why here:** each is useful alone, touches only core and the design system, and 11.7's update flow is what the package in leg 3
carries to every app.

**Technical notes:** the manifest is `apps/core/app/manifest.ts` with icons from `apps/core/src/pwa.ts`; the screenshots are served
like the icons (`src/branding/default-icons.ts`), so the image gains no file. The worker is `apps/core/src/sw/source.ts`, a string;
its acceptance tests are in `apps/e2e`. The registration is `apps/core/app/service-worker-registration.tsx`. The install hint and the
update notice are design-system components with stories and gallery entries (`docs/design-system.md`).

**Do not proceed if:** a manifest member would vary by who asks, or the update notice would need the worker to cache anything new.

### Leg 2 — On the devices

**Epic tasks:** 11.3 (its outstanding rows), 11.8

**Why here:** the handoff (leg 5) and what the apps must declare (legs 3 and 4) depend on what the devices do; 11.3's rows have
waited for the same person and devices.

**Technical notes:** the throwaway pair of pages lives outside the image (a branch-only folder or a gist), served on two hosts of the
suite's domain over https. Record browser and OS versions in each cell of research 0010's matrix.

**Do not proceed if:** no platform hands the link over: then A5 is withdrawn, leg 5 shrinks to 11.10, and legs 3 and 4 drop
`handle_links`.

### Leg 3 — `@sovereignfs/pwa` and the template

**Epic tasks:** 11.11, 11.12

**Why here:** after leg 1 (the update flow) and leg 2 (what the manifest must declare), so the apps are moved once.

**Technical notes:** extract from `tusk/src/sw/source.ts`, `tusk/app/manifest.ts`, `fjord/clients/web/src/pwa/` and
`fjord/clients/web/src/security/csp.ts`. Publishing a new package follows `docs/releasing.md` and its first changelog section. The
template is `tools/create/template/app`, its tests `tools/create/src/app.test.ts`; it has no proxy or CSP today, so 11.12 adds one.

**Do not proceed if:** the package would need anything from core, or a template test cannot see a generated app's worker register.

### Leg 4 — The deployed apps

**Epic tasks:** 11.13

**Why here:** the package and the checklist exist, so each app is changed once.

**Technical notes:** each app repository is committed on its own `develop`, one change per app, with that app's version bump. Seen
gaps: no `id` except fjord; no `appleWebApp` in ledger, shopper, tally; shopper's single `theme-color`; ledger's missing `/shell`;
`theme_color` differs (fjord white, the rest `#18181b`).

**Do not proceed if:** adding `id` is seen to make an installed app a different app on any device.

### Leg 5 — Tiles and shortcuts open apps

**Epic tasks:** 11.9, 11.10

**Why here:** last, because it relies on what the devices showed and on the apps declaring `launch_handler` and `handle_links`.

**Technical notes:** the launcher is `apps/core/app/launcher.tsx`; `AppTile` is in the published `@sovereignfs/ui` and must stay
framework-agnostic. The display mode is read only in the click handler. Shortcuts are `apps/core/src/shortcuts/manager.ts`, the
address check `apps/core/src/clients/validate.ts`; the new column needs every dialect and `sv-security-check`.

**Do not proceed if:** the decision can only be made in render, or the deep-link check needs a deny-list alone.

## Risks

- **Browser behaviour moves.** Chrome's capture rules changed in 139 and 151; leg 2's results date quickly. Re-run the matrix before
  leg 5 if months pass.
- **Orphaned installs.** A manifest `id` that does not match the identity a browser derived makes a second app. Leg 4 checks first.
- **A new published package** is a contract: a breaking change needs a minor bump at least and an upgrade note.
- **The update notice** changes when a release reaches people; an open window that never reloads runs old code until it does.

## Kill criteria

If leg 2 shows that no platform hands a link to another installed app, A5 is withdrawn and leg 5 keeps only shortcuts; legs 1, 3
and 4 stand on their own (a fuller install, one package, and apps that install well).
